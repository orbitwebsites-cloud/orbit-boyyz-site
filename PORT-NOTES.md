## What was ported verbatim (and how)

- **Content was extracted programmatically**, not retyped (`scripts/port/extract.mjs`, `extract-legal.mjs`): the old arrays are parsed with the TypeScript AST and evaluated, then written to typed modules — `src/content/blog.ts` (45 posts incl. titles, descriptions, `updated` dates, audience, takeaways, sections, 3 posts' FAQs, clusters, landing links, buyer-intent slugs), `landing.ts` (town/industry page data, Central NJ lists, old FAQ list, old services/areas cards), `growth.ts`, `brief.ts`, `legal.ts`.
- **SEO metadata + JSON-LD** (`src/lib/legacy-seo.ts`) is the old `prerender.mjs` code itself (page-meta table, organization/website/Service/BreadcrumbList/FAQPage/BlogPosting/Blog/WebAPI/AboutPage/WebPage builders), copied by `scripts/port/gen-legacy-seo.mjs` and only given TypeScript types. `src/lib/legacy-meta.tsx` reproduces `buildHead()`: exact `<title>` (no template suffix), description, absolute canonical `https://orbitboyzz.me/...`, RSS alternate, robots `index,follow,max-image-preview:large,max-snippet:-1`, og/twitter tags with the old og:image, `og:type=article` on posts.
- `lib/quoteEstimate.ts` and `lib/leadForm.ts` are byte copies. API handlers keep the same validation messages, status codes, JSON envelope `{error:{code,message,hint?}}`, `Allow` headers on 405, and `Vary: Accept, Accept-Encoding`.
- `MARKDOWN_PAGES` and `wantsMarkdown()` copied verbatim into `src/proxy.ts` (`scripts/port/gen-proxy.mjs`); the growth.orbitboyzz.me → `/growth` rewrite is kept.
- JSX-only copy (landing pages, Ewing, Central NJ, Developers, OrbitBoyzz, Growth, forms) was ported by hand and then **verified automatically**: the checker takes every text block (≥24 chars) from the live old page's `<main>` and requires it on the new page — **1,609 segments across all 70 ported pages, 0 missing**.

## Could not port 1:1 / open items

1. **`Vary: Accept` on HTML pages under `next start`.** The proxy sets `Vary: RSC, Next-Router-State-Tree, Next-Router-Prefetch, Next-Router-Segment-Prefetch, Accept, Accept-Encoding`, but Next 16's app-page renderer overwrites `Vary` (`res.setHeader('Vary', …)` in `app-page-runtime.js`) for prerendered pages when self-hosted. Markdown responses and `/api/*` do carry `Accept, Accept-Encoding`. Verify the header on the Vercel preview (see results section); if Vercel also drops it, the options are a Vercel-level header rule or accepting it (markdown is only served when explicitly requested).
2. **Quote estimator numbers: old source ≠ current production.** Ported logic is the old repo HEAD (`be7b953`): new website = **$750–$750, $0/mo**; AI = $5,000–$15,000 + **$1,500–$2,500/mo**. The live production API/page still returns an older build ($150–$400 + $100–$300/mo; AI $750+/mo). The page copy/metadata all match live; only these computed numbers differ. Owner should confirm which pricing the estimator should show.
3. `/api/<unknown>` message: live says `No API endpoint exists at /api/nope?...notfound=nope.` (a Vercel catch-all artifact); new says `…at /api/nope.` Same status, code and hint.
4. The old `BlogPost` component also injected duplicate in-body `BlogPosting`/`FAQPage` scripts; only the canonical prerender graph is emitted now (one JSON-LD block per page, identical to the old head block).
5. `/form` was never prerendered (live returns 404) and is not in the sitemap; it now exists with the old default `<head>` title/description and stays out of the sitemap.
6. Malformed JSON bodies to `/api/quote-estimate` now return `400 invalid_json` (Vercel's helper behaviour isn't reproducible exactly).
7. Lead form success path (HubSpot + formsubmit email) was **not executed** — it sends real email/CRM records. Only validation (400) and 405 paths were tested. Without `HUBSPOT_PRIVATE_APP_TOKEN` it behaves like the old handler: logs, skips CRM, still sends the formsubmit confirmation, returns `200 {received:true, crmSynced:false, emailSent:…}`.
